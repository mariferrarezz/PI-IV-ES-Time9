Os campos de credencial permanecem no Firebase. Mensagens da API são exibidas sem substituir os erros Java por mensagens locais; os erros estruturais do Zod permanecem genéricos. Nenhum dos testes isolados comprova o percurso completo no Chrome.

A data de plantio usa meia-noite no fuso IANA `America/Sao_Paulo` antes do envio e o mesmo fuso na exibição. O aplicativo rejeita dias cuja meia-noite seja inexistente ou ambígua. Os testes incluem datas antes e depois do fim do horário de verão. O registro sintético foi adicionado à conta e ao talhão de teste existentes e não foi removido.

As etapas de CPF e telefone chamam rotas públicas de validação (`POST /validacao-cadastro/cpf` e `/telefone`), sem Firebase, usando comandos Java por campo e conferindo no MongoDB se o dado já está cadastrado; o cadastro final continua validando novamente todos os campos. Como as rotas são públicas, elas revelam se um CPF ou telefone já existe; o time aceitou isso em 23/11 por ser um projeto acadêmico sem dados reais. O teste de denúncia criou `6b038622dde010951f25e4d9`, pendente, em uma experiência de demonstração que continua aprovada. Nenhuma limpeza foi executada.
